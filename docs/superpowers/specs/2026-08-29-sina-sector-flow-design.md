# 新浪板块资金流与准实时展示设计

## 目标

将项目的默认数据源切换为新浪财经板块资金流接口，使采集器可以在交易时段获取行业和概念板块的资金净流入，并在每次成功采集后更新当天 JSON；前端自动轮询当天 JSON，形成约 5 分钟级的准实时曲线。

## 已确认的数据源与口径

- 主数据源：`https://vip.stock.finance.sina.com.cn/quotes_service/api/json_v2.php/MoneyFlow.ssl_bkzj_bk`
- 新浪行业：`fenlei=0`
- 概念板块：`fenlei=1`
- `fenlei=2`（证监会行业）暂不接入，保留后续扩展空间。
- 新浪返回的 `netamount` 是板块净流入金额，单位为元；它不等价于东方财富 `f62` 的“主力净流入”。项目内部沿用 `main_net` 字段以保持现有数据库和前端兼容，但文档与页面状态明确标注为“板块净流入（新浪口径）”。
- 新浪 `avg_changeratio` 为小数比例，导入时转换为百分比数值。
- 新浪接口当前页面通常以 5 分钟节奏更新，采集器默认 5 分钟轮询；间隔期间由导出阶段前值填充。

## 组件设计

### 新浪适配器

新增 `sina.py`，只负责 HTTP 请求、分页、重试、JSON 校验和字段标准化。输出与现有 `eastmoney.fetch_sector_snapshot()` 兼容的字典结构：`sector_type`、`code`、`name`、`pct_chg`、`main_net`、四档资金字段（新浪板块接口没有时为 `None`）和 `raw`。

### 采集器

`collector.py` 默认调用新浪适配器，保留 `--provider eastmoney` 作为人工备用选项。采集成功写入 SQLite 后，立即调用导出逻辑写入 `data/YYYY-MM-DD.json`。采集间隔默认 300 秒，可通过命令行覆盖。失败时不生成伪数据、不清零已有数据，并继续下一轮。

### 导出与前端

`export.py` 抽出可复用的 JSON 写入函数，并在导出结果中增加数据口径字段。`web/viewer.html` 默认读取中国时区当天文件，显式使用 `?date=mock` 时读取模拟数据；对真实日期文件每 60 秒轮询，页面显示最近刷新时间。页面保留原有曲线、tooltip 和回放功能。

### 配置与数据安全

`config.yaml` 增加 `provider: sina`、轮询间隔和新浪分类映射。运行生成的 SQLite 数据库及当天 JSON 不纳入 Git；模拟 JSON 继续保留。所有中文文件读写显式使用 UTF-8。

## 错误处理

- HTTP、超时、JSON 格式错误和空列表统一转为可读的 `SinaError`，每页独立重试。
- 第 1 页失败时本轮采集失败；后续页失败时保留已取到的数据并记录“部分分页”告警。
- 新浪返回重复板块代码时去重。
- 页面请求失败时保留当前图表，不覆盖有效状态，并在状态栏提示；成功后替换数据并重绘。
- 东方财富原模块及其探测脚本不在本次主路径中改造。

## 验证标准

1. 单元测试覆盖新浪字段解析、分类映射、分页/重试、数据库写入和 JSON 导出。
2. 前端数据契约测试确认真实日期文件可被页面轮询，模拟数据仍可加载。
3. 当前环境对新浪板块接口至少完成一次真实请求，返回行业与概念板块数据。
4. 页面通过本地 HTTP 服务返回 200，模拟 JSON 仍为 16 个板块 × 240 点。
5. Git 工作区只包含预期源码、文档和测试改动，运行数据不进入提交。
